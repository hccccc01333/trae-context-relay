## 发现的问题

1. **`.trae` Skill 无法作为文件证据（已修复）。**  
   显式传入 `.trae/skills/context-relay/SKILL.md` 时，该路径因位于隐藏目录被排除，capture 返回 warning。这符合当时“隐藏目录一律不保存”的安全策略，但也意味着 TRAE 集成层本身无法被哈希验证。  
   修复提交 `e564ece`：允许 `.trae/skills/**` 公开能力文件进入证据，Git 状态也会显示该路径的变化；`.env`、私钥、`secrets/`、隐藏子目录和 `node_modules` 仍被排除。新增的单元与集成测试覆盖了公开 Skill 文件、敏感文件和隐藏子目录。

2. **真实新会话已能恢复状态，但尚未测量开发行为。**  
   2026-10-27 14:57 的独立 TRAE 任务证明新会话能保留 6 / 6 决策、核验 14 / 14 证据，并正确识别 7 个 `done_claimed`。  
   但该会话只执行了 resume，没有继续开发，也未与 Markdown 摘要对照，因此重复任务数和相对 Token 成本仍未测量。

3. **Token 数不是 tokenizer 实测值。**  
   没有引入额外 tokenizer 依赖。表中数字使用可复现的粗略估算：CJK 字符按 1 token/字，其他字符按 4 字符/token，向上取整。后续 Benchmark 应改用固定模型 tokenizer 实测并记录模型名称。

## 后续实验协议（v0.4 基线）

1. 在同一个 Git 基线上准备两份恢复材料：ContextRelay `resume` 输出与普通 Markdown 摘要。
2. 分别在新会话中只提供其中一份，并给出相同的新任务。
3. 记录：
   - 是否重复实现已完成功能（重复任务数）；
   - 是否保留关键技术决策（决策保留率）；
   - 是否把 `done_claimed` 误当作已验证（错误完成声明数）；
   - 首次可用产出所需的轮次；
   - 输入 Token、输出 Token 与总成本（使用固定 tokenizer 实测）。
4. 每个条件至少重复 3 次，记录均值与原始样本。
