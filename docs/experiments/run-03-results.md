# run-03：ContextRelay vs Markdown 摘要（单轮案例）

> 这是一次单轮、单模型、单任务的受控 A/B，用于验证“交接材料过期时，下一次会话会不会继续执行旧决策”。它不是普遍性收益结论，Token 用量不可得。

## 实验设置

- 模型：DeepSeek V4.1 Flash（两臂相同，用户提供）
- 基线：封存后的 v0.3 仓库，两臂 HEAD 相同，仓库内不含任务卡、协议、评分表与 fixtures
- 任务：实现 `context-relay diff`，任务卡 v2 不提示实验假设，也不规定默认输出格式
- A 组：用 `context-relay resume` 读取 H2 快照
- B 组：用一份停留在 H1 的 Markdown 摘要
- 顺序：B → A，串行；两臂均只收到一条入口提示，无额外纠偏
- 材料长度：A 交接材料 3795 字符，B 摘要 1149 字符，任务卡 2565 字符
- 人工干预：0

## 结果

| 指标 | A：ContextRelay | B：Markdown 摘要 |
| --- | ---: | ---: |
| 最新有效决策保留 | 3/3 | 2/3 |
| 执行已废弃决策 | 0 | 1 |
| 重复任务 | 0 | 0 |
| 错误完成声明 | 0 | 0 |
| 人工干预 | 0 | 0 |
| 验收 | 通过 | 通过 |
| 测试 | 27 | 29 |
| 平台积分 | 23.39 | 18.03 |
| 会话时长 | 13m 9s（789s） | 11m 4s（664s） |
| Token | 不可得 | 不可得 |

## 关键差异

H2 把 H1 的“默认输出 JSON”标记为 `superseded`，改为默认人类可读摘要。

- A 读取了 H2，保留 3 条 `active` 决策，明确不执行旧决策，并上报了 2 个未解决冲突。
- B 只拿到 H1，按“默认 JSON”实现，并把测试写成围绕 JSON 默认。B 通过了它那一轮的验收，因为验收标准是“按交接材料执行”；它错的是相对 H2 的真实状态。

两臂都没有重复实现 T1/T2，也没有修改 `context.ts`、`migrations.ts` 或 `schema.ts`。因此这次没有观察到“减少重复任务”的差异。

## 代价

- A 的平台积分比 B 高 **29.7%**（23.39 vs 18.03）。
- A 的会话时长比 B 长 **18.8%**（789s vs 664s）。
- A 的交接材料是 B 的 **3.3 倍**（3795 vs 1149 字符）。

这不是“更便宜”的证据。它买到的是“下一次会话知道哪些决策已经作废、哪些冲突还没解决”。

## 限制

- 只有一轮干净的 A/B；
- 只有一个模型、一个任务；
- Token 用量拿不到，平台积分由用户提供，不能换算成 Token；
- 任务本身没有制造重复实现压力；
- 样本不足以发布总体量化结论。

完整协议与假设见 [Benchmark 协议](benchmark-protocol.md)。
